# Contributing to Zingoodle

Thank you for your interest in contributing to Zingoodle! This project is primarily a personal learning repository, but insights and improvements are welcome.

## How to Contribute

1. **Fork the repository** on GitHub
2. **Create a feature branch** from `main`:
   ```bash
   git checkout -b feature/your-feature-name
   ```
3. **Make your changes** following the project conventions
4. **Ensure invariants are maintained** - check relevant `docs/invariants/` files
5. **Test your changes** thoroughly
6. **Commit your changes** with clear, descriptive messages
7. **Push to your fork** and **submit a pull request**

## Guidelines

### Code Style

- Follow the language-specific conventions (e.g., consistent naming, formatting)
- Write clear, readable code with comments
- Maintain the first-principles approach - avoid unnecessary abstractions

### Documentation

- Update relevant documentation in `docs/`
- Add invariants for new systems before implementation
- Document breaking cases and lessons learned in `docs/postmortems/`

### Testing

- Test your code thoroughly
- Include edge cases and failure scenarios
- Document test cases where appropriate

### Commit Messages

- Use clear, descriptive commit messages
- Start with a verb (Add, Fix, Update, etc.)
- Keep the first line under 50 characters

## Areas for Contribution

- **DSA Implementations**: New algorithms or improved existing ones
- **System Enhancements**: Better implementations of existing systems
- **Documentation**: Clarifications, additional examples, tutorials
- **Tools**: Build scripts, testing frameworks, utilities
- **Bug Fixes**: Identified issues in existing code

## Code of Conduct

Be respectful and constructive in all interactions. This is a learning project - focus on education and improvement.

## Questions?

If you have questions about contributing, open an issue or contact the maintainer.

Thank you for helping make Zingoodle better! 🚀
